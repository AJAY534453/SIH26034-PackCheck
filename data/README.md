# POCKET dataset architecture

This directory holds **real packaged-commodity evidence** and the ground truth used to measure
extraction quality honestly. It is deliberately separate from the application's runtime storage
(`storage/`), which holds inspection evidence uploaded through the app.

Nothing here is downloaded automatically, and no metric in the docs is derived from these folders
unless a human entered the ground truth.

```
data/
├── raw/                    # photos exactly as captured, one folder per product (immutable)
│   └── <product_id>/
│       ├── front.jpg
│       ├── back.jpg
│       └── side.jpg
├── annotations/            # human ground truth, one JSON per product
│   └── <product_id>.json
├── splits/                 # generated product-level splits (never edited by hand)
│   ├── train.txt
│   ├── validation.txt
│   └── test.txt
├── benchmark/              # single-image benchmark used by scripts/run_benchmark.py
│   ├── manifest.csv
│   └── ground_truth/<image>.json
└── difficult_cases/        # evidence that failed extraction, kept as regression material
```

## Why product-level, multi-view

One package distributes declarations across surfaces:

| surface | typical declarations |
|---|---|
| front | brand, product name, MRP, net quantity |
| back  | manufacturer + address, FSSAI, consumer care, ingredients |
| side  | batch/lot, MFG/PKD, EXP/USE BY |

So the unit of annotation is a **product** (all its views), never a single image. A field that is
absent from one view is *not absent from the package* — POCKET reports `MISSING` ("not detected in
supplied images"), and only a human can confirm real absence.

## Annotation schema

`annotations/<product_id>.json`:

```json
{
  "product_id": "p0001",
  "category": "biscuit",
  "package_type": "pouch",
  "annotator": "inspector-name",
  "annotated_at": "2026-09-15T10:00:00Z",
  "views": [
    {"file": "front.jpg", "view": "front", "quality": "GOOD"},
    {"file": "back.jpg",  "view": "back",  "quality": "FAIR"}
  ],
  "fields": {
    "mrp": {
      "value": "5.00",
      "raw_text": "MRP Rs. 5.00",
      "image": "front.jpg",
      "bbox": [120, 340, 260, 370],
      "confidence": 1.0
    },
    "net_quantity": {"value": "34.5", "unit": "g", "raw_text": "28.4 g + 6.1 g EXTRA = 34.5 g"},
    "batch_lot": {"value": "B07269L"},
    "date_packing": {"value": "2026-07-20"},
    "date_expiry": {"value": "2027-01-19"},
    "manufacturer": {"value": "Example Industries Limited"},
    "manufacturer_address": {"value": "…"}
  }
}
```

Rules:

* `value` is the **normalized** reading; `raw_text` keeps what was printed.
* `bbox` is `[x1, y1, x2, y2]` in **original image pixels**, and is required only when the source
  region is claimed. It is what the EvidenceViewer highlights, so it must map to the original file.
* **Omit fields that are not visible.** Never write a guessed value, and never write an empty
  string to mean "absent" — omitted means "this ground truth says nothing about that field".
* Field names are the app's field names (`backend/extraction/field_schema.py`) so evaluation maps
  1:1 with production output.

## Splits

* Splits are by **product_id**, never by image. Different photos of the same product must never
  appear in both `train` and `test` — that would leak the product and inflate every metric.
* Generated by `scripts/dataset.py split` (seeded and reproducible), written to `data/splits/`.
* `data/splits/*.txt` hold one product id per line.

## Validation

Run before any evaluation or training:

```
.venv/Scripts/python scripts/dataset.py validate
```

It checks: missing image files, images with no annotation, unreadable/invalid annotation JSON,
duplicate product ids, duplicate image content (SHA-256), empty field values, bbox sanity, and
train/test product leakage. It writes `docs/DATASET_VALIDATION_REPORT.md`.

## Evaluation (real evidence only)

```
.venv/Scripts/python scripts/run_benchmark.py
```

Reports per field: correct (exact), correct (normalized), wrong, not detected, false positives and
mean confidence, over the images listed in `benchmark/manifest.csv` with real ground truth. When no
ground truth exists it prints **"insufficient data"** — it never invents numbers.

Synthetic variation testing (thousands of generated declaration renderings) lives in
`backend/testing/robustness.py` and is reported separately as **synthetic**, never as real accuracy:

```
.venv/Scripts/python scripts/run_benchmark.py --synthetic   # if enabled, see docs/TESTING.md
```

## External datasets (RPC and similar)

The Retail Product Checkout (RPC) dataset is ~27 GB. It is **not** required and is not downloaded by
anything here. RPC provides retail product photos with viewpoint/clutter/occlusion variation but
**no Legal Metrology declarations** (no MRP, net quantity, batch, MFG/EXP, FSSAI). If used, it is a
secondary *visual robustness* set for detection/cropping experiments only — never a source of
declaration ground truth, and never cited as such.

Other public datasets are admitted only after checking their licence and confirming the fields they
annotate are relevant; none are assumed to contain Legal Metrology labels.

## Quality over raw size

Priority is *useful variation with reliable ground truth*, not image count. A hundred genuinely
annotated products spanning pouches, boxes, bottles, jars, cans, cartons, sachets and tubes — each
with front/back/side views and some deliberately difficult shots (blur, glare, angle, small text) —
is more valuable than thousands of unrelated retail photos.
